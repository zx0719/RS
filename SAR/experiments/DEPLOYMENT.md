## 一、硬件部署要求

### 1.1 推理（生产部署）

| 配置级别 | GPU | 显存 | CPU | 内存 | 存储 | 说明 |
|---------|-----|------|-----|------|------|------|
| **最低** | NVIDIA T4 / RTX 3080 | 8 GB | 8核 | 16 GB | 50 GB SSD | 单张图像串行处理，约 5~10s/张 |
| **推荐** | NVIDIA A10 / RTX 4090 | 24 GB | 16核 | 32 GB | 200 GB SSD | 支持批处理，约 2~3s/张 |
| **高性能** | NVIDIA A800 / A100 | 40~80 GB | 32核 | 64 GB | 1 TB NVMe | 大批量并发，<1s/张 |

> 当前开发环境：2× NVIDIA A800 80GB PCIe，实测单卡推理约 **2~3s/张**（模型常驻显存时）。

### 1.2 模型显存占用明细

| 组件 | 显存占用 | 备注 |
|------|---------|------|
| YOLOv8m-OBB（best.pt） | ~1.5 GB | FP32推理；FP16约 0.8 GB |
| Qwen3-4B（本地LLM） | ~8 GB | FP16；量化INT4约 3 GB |
| 图像缓存（640×640 batch=8） | ~0.5 GB | 推理时临时占用 |
| **合计（FP16）** | **~10 GB** | T4/3080 8GB 仅能跑检测器，不含LLM |

> 若不使用本地LLM（走API模式），仅需 **2 GB** 显存即可运行检测器。

### 1.3 CPU-only 模式

YOLOv8-OBB 支持纯 CPU 推理，但速度显著下降：

| 硬件 | 推理速度 | 适用场景 |
|------|---------|---------|
| 8核 CPU（Intel Xeon） | ~15~30s/张 | 低频次离线分析 |
| GPU（T4） | ~2~5s/张 | 常规部署 |
| GPU（A800） | ~0.5~2s/张 | 高吞吐生产 |

启用 CPU 模式：`--device cpu`

### 1.4 软件环境

| 组件 | 版本要求 |
|------|---------|
| Python | 3.10+ |
| PyTorch | 2.0+（推荐 2.4） |
| CUDA | 11.8+（推荐 12.1） |
| ultralytics | 8.4+ |
| python-docx | 1.1+ |
| Pillow | 10.0+（中文字体渲染） |
| rasterio | 1.3+（GeoTIFF坐标解析） |

## 二、SAR图像分辨率说明

### 2.1 主流SAR卫星分辨率对照

| 卫星 | 国家 | 分辨率（GSD） | 幅宽 | 极化 | 备注 |
|------|------|-------------|------|------|------|
| 高分三号（GF-3） | 中国 | 1~500m（多模式） | 10~650km | 全极化 | 聚束模式最高 1m |
| 高分三号02星 | 中国 | 1~10m | 10~100km | 全极化 | 2022年发射 |
| 陆探一号（LT-1） | 中国 | 3~25m | 30~400km | 全极化 | 2022年双星组网 |
| Sentinel-1 A/B | 欧洲 | 5×20m（IW模式） | 250km | VV+VH | 免费开放，最常用 |
| TerraSAR-X | 德国 | 0.25~16m | 4~100km | 全极化 | 商业，聚束最高 0.25m |
| COSMO-SkyMed | 意大利 | 1~100m | 10~200km | 全极化 | 商业/军用双用途 |
| RADARSAT-2 | 加拿大 | 3~100m | 20~500km | 全极化 | 商业 |
| ALOS-2 PALSAR-2 | 日本 | 1~100m | 25~490km | 全极化 | L波段，穿透力强 |
| Capella Space | 美国 | 0.35~1m | 5~10km | VV | 商业，超高分辨率 |
| ICEYE | 芬兰 | 0.5~3m | 5~100km | VV | 商业，小卫星星座 |

### 2.2 分辨率与目标可检测性关系

| GSD（地面分辨率） | 可检测目标 | 典型应用 |
|-----------------|-----------|---------|
| **0.1~1m** | 车辆、小型舰艇、飞机细节、导弹发射架 | 精确打击情报、目标识别 |
| **1~3m** | 舰船（可分型号）、飞机（可分机型）、坦克群 | 军事目标精细识别 |
| **3~10m** | 舰船（可计数）、飞机（可计数）、港口设施 | **本系统当前主要适用范围** |
| **10~30m** | 大型舰船、机场、港口、桥梁 | 区域态势感知 |
| **30m以上** | 港口/机场整体、大型基础设施 | 宏观监视 |

> 本系统 v4 模型训练数据（SSDD/SARDet_100K）主要覆盖 **3~10m** 分辨率，目标尺寸在图像中约 **10~100 像素**。

### 2.3 YOLOv8-OBB 输入规格

| 参数 | 值 | 说明 |
|------|-----|------|
| 输入尺寸 | 640×640 | 训练/推理统一，自动letterbox缩放 |
| 最小可检测目标 | ~10×10 像素 | 低于此尺寸漏检率显著上升 |
| 最优目标尺寸 | 30~200 像素 | 检测精度最高区间 |
| 支持格式 | GeoTIFF / JPEG / PNG / BMP | GeoTIFF保留地理参考信息 |
| 波段 | 单波段灰度（SAR强度图） | 多波段取第一波段 |

### 2.4 分辨率对检测效果的影响

```
分辨率 1m：目标像素大，特征丰富，检测精度高，但幅宽小（覆盖范围有限）
分辨率 3m：舰船/飞机可清晰分辨，本系统最优输入
分辨率 10m：目标像素少，小目标（坦克/车辆）漏检率上升
分辨率 30m：仅大型目标（航母/港口）可检测，坦克/飞机基本不可见
```

**建议输入分辨率：1~10m**（对应目标在640×640图像中占 20~200 像素）

## 三、端到端性能基准

> 测试环境：NVIDIA A800 80GB，单卡，模型常驻显存，sar-intel conda环境

| 阶段 | 耗时 | 备注 |
|------|------|------|
| 模型加载（首次） | ~8~10s | YOLO权重加载 + CUDA初始化 |
| M1 预处理 | <0.1s | GeoTIFF元数据解析 |
| M2 YOLOv8-OBB推理 | **0.5~2s** | 640×640，单张，GPU |
| M3 坐标地理化 | <0.1s | 仿射变换，纯CPU |
| M4 证据融合 | <0.1s | 纯Python |
| M5 通报生成（规则模板） | <0.1s | 无LLM |
| M5 通报生成（Qwen3-4B本地） | 5~15s | 依赖GPU显存余量 |
| M6 Word组装 | <0.5s | python-docx |
| **全流程（规则模板）** | **~2~5s/张** | 模型已加载时 |
| **全流程（本地LLM）** | **~10~20s/张** | 含Qwen3-4B推理 |

> 当前 `run_v4_test_report.py` 每次启动重新加载模型，冷启动约 **5~70s**（含CUDA初始化）。
> 批量处理时建议将模型加载提到循环外，可将平均耗时压到 **2~3s/张**。

## 四、部署建议

### 离线/内网部署（推荐）

```
[SAR图像输入] → [本系统服务器（GPU）] → [Word报告输出]
                    ↑
              无需外网连接
              LLM本地运行（Qwen3-4B）
              所有数据不出内网
```

最低配置：**RTX 3080 10GB + 32GB内存**（仅检测器，LLM走API）  
推荐配置：**A10 24GB + 64GB内存**（检测器 + 本地LLM一体化）

### API模式部署（轻量）

检测器本地运行，LLM调用外部API（OpenAI兼容接口）：
- 显存需求降至 **2 GB**
- 需要网络连接到LLM服务
- 适合测试环境或非涉密场景
