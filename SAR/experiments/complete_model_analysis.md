## 三、差距详细分析

### 🔴 高风险 (阻塞交付)

#### 1. 机场检测能力缺失
**现状**:
- v4-multiclass无airport类别
- 预留了runway/taxiway/apron/hangar等子类ID (5-13)，但未标注训练

**影响**:
- 无法完成"机场"目标检测任务
- 无法满足"飞机+机场"双目标场景

**解决方案**:
- **方案A**: 场景分类器 (ResNet/ViT全图分类为airport/harbor/open_sea等)
- **方案B**: 目标检测器 (标注runway/apron等机场设施作为新类别)
- **预估工期**: 方案A 1-2周, 方案B 3-4周

#### 2. 港口检测性能不足
**现状**:
- v4-multiclass包含harbor类别
- 但整体recall仅82.9%，无法确认harbor单独达标

**影响**:
- 可能无法满足"港口检测率≥92%"要求

**解决方案**:
- 重新验证v4-multiclass的per-class性能
- 如harbor recall<92%，需增加港口训练数据
- **预估工期**: 1-2周验证 + 可能2-3周重训

---

### 🟡 中风险 (功能不完整)

#### 3. Per-class性能不透明
**现状**:
- v5-2class-4的P=93.4%, R=93.3%是**平均值**
- 无法确认飞机和船舶分别是否达标

**解决方案**:
```bash
# 运行per-class验证
yolo val model=v5-2class-4/best.pt data=dataset.yaml split=val
# 查看confusion_matrix.png和per-class metrics
```
**预估工期**: 1天

#### 4. 尺寸过滤缺失
**现状**:
- 检测器输出所有目标，未按真实尺寸筛选
- 要求: 飞机>20m, 轮船>80m

**影响**:
- 可能误检小型目标 (如游艇、无人机)
- 不符合任务指标定义

**解决方案**:
```python
# 后处理伪代码
for obj in detections:
    pixel_length = max(obj.width, obj.height)
    real_length_m = pixel_length * GSD  # GSD from metadata
    if obj.class == 'aircraft' and real_length_m < 20:
        continue  # 过滤
    if obj.class == 'ship' and real_length_m < 80:
        continue  # 过滤
```
**预估工期**: 2-3天

---

### 🟡 低风险 (性能优化)

#### 5. 检测速率严重不足
**现状**:
- YOLOv8m单张640×640推理约15-20ms
- 单图速率: (640×640) / 0.02s ≈ 20 MPix/s
- **要求: 502 MPix/s** (差距25倍)

**影响**:
- 无法满足实时处理要求 (识别时长≤1×成像时长)
- 可能延时处理也压力大 (识别时长≤4×成像时长)

**解决方案优先级**:

| 方案 | 预期提升 | 复杂度 | 预估工期 |
|------|----------|--------|----------|
| **批处理优化** | 2-3× | 低 | 1周 |
| **TensorRT量化** | 2-4× | 中 | 2周 |
| **模型剪枝/蒸馏** | 1.5-2× | 中 | 2-3周 |
| **换YOLOv8n/s** | 3-5× (牺牲2-3% mAP) | 低 | 1周 |
| **多GPU并行** | N× (N卡) | 中 | 2周 |
| **FPGA/专用硬件** | 10-50× | 高 | 1-2个月 |

**组合方案** (最可行):
- YOLOv8s (轻量级) + TensorRT + batch=16
- 预期: 20 → 60 → 120 → 240 MPix/s
- **仍差距2倍**，需要多GPU或继续优化

**关键确认项**:
❓ 502 MPix/s是单卡还是允许集群？  
❓ 能否接受YOLOv8s (牺牲2-3% mAP换取3-5×速度)？
