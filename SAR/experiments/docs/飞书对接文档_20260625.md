## 一、当前进展汇报

### 1.1 项目背景

基于SAR卫星图像实现军事目标自动检测，目标是支持**飞机（>20m）、轮船（>80m）、机场、港口**四类目标的实时/延时检测。

### 1.2 已完成的模型训练

目前已训练了**5个版本的YOLOv8-OBB旋转框检测模型**，按时间顺序如下：

| 版本 | 目标类别 | 类别数 | 精确率(P) | 召回率(R) | mAP@50 | 训练状态 |
|------|----------|--------|-----------|-----------|--------|----------|
| v1-ship | 船舶 | 1 | **96.2%** | **97.5%** | **98.98%** | ✅ 完成 |
| v2-sardet | 船舶 + 飞机 | 2 | **92.4%** | **91.0%** | **95.5%** | ✅ 完成 |
| v4-multiclass | 船舶 + 飞机 + 坦克 + 桥梁 + 港口 | 5 | 84.9% | 82.9% | 87.54% | ⚠️ 召回率不足 |
| **v5-2class-4** | 船舶 + 飞机 | 2 | **93.4%** | **93.3%** | **95.98%** | ✅ **推荐模型** |

### 1.3 与公司指标对比（基于v5-2class-4）

| 指标 | 公司要求 | 我方性能 | 状态 |

### 1.4 数据集与训练详情

#### 数据规模演进

v1 → v2 → v4/v5 的数据量增长是**逐步合并多个数据源**的结果，并非凭空产生：

| 阶段 | 数据集 | 训练图 | 验证图 | 数据来源 | 说明 |
|------|--------|--------|--------|----------|------|
| v1 | SSDD | 789 | 139 | SSDD公开集 | 仅船舶，官方划分 |
| v2 | SARDet-aircraft | 14,553 | 1,972 | SARDet_100K 单类子集 | 仅抽取aircraft类别 |
| v4 | **multiclass** | **135,938** | **15,317** | SSDD + SARDet_100K全量 + MSAR | 5类合并，全量数据 |
| v5 | **2class** | **118,814** | **13,342** | 从v4提取 ship+aircraft | 剔除tank/bridge/harbor |

> **为什么 v2 只有 ~1.6 万，v4 却跳到 ~15 万？**
>
> v2 只从 SARDet_100K 中**抽取了 aircraft 这一个类别**的子集用于迁移学习实验。
> v4 则是将 **SARDet_100K 全部 94K 张图像（含 ship/aircraft/tank/bridge/harbor 全部 5 类标注）**，加上 SSDD（~1K 张 ship 标注）和 MSAR（桥梁标注），合并为统一的多类数据集。数据量从单类子集扩展到全量合并，自然增长了约 10 倍。

#### 各版本数据集明细

**v1-ship (SSDD)**
- 数据来源：SSDD (SAR Ship Detection Dataset)，公开SAR舰船数据集
- 规模：789 张训练 + 139 张验证 + 232 张测试 = 1,160 张
- 标注框：~1,756 个旋转框
- 类别：仅 `ship` (1类)
- 格式：YOLO OBB (9列: class x1 y1 x2 y2 x3 y3 x4 y4)
- 用途：验证YOLOv8-OBB在SAR船舶检测上的可行性

**v2-sardet-aircraft**
- 数据来源：SARDet_100K（仅抽取 aircraft 类别）
- 规模：14,553 张训练 + 1,972 张验证，28,466 个标注框
- 类别：仅 `aircraft` (1类)
- 此阶段目的：迁移学习实验，让基于 ship 预训练的模型学会飞机特征
- 备注：此子集已合并进 v4/v5

**v4-multiclass ⭐ 多类核心数据集**
- 数据来源（三源合并）：
  - SSDD：~1K 张，ship 标注
  - **SARDet_100K 全量**：~94K 张，覆盖 ship/aircraft/tank/bridge/harbor 5 类
  - MSAR：桥梁补充标注
- 合并后规模：**135,938 张训练 + 15,317 张验证**（全量合并，未采样）
- 类别：**5类** (ship / aircraft / tank / bridge / harbor)
- 固定ID方案：ID 0-4 不可更改，预留 ID 5-13 供后续机场设施标注
- 模型表现：整体 recall 82.9%，未达公司要求的 92%（5类混合相互干扰）

**v5-2class 🏆 当前推荐数据集**
- 数据来源：从 v4 中提取 ship + aircraft 两类，**剔除 tank/bridge/harbor 以减少类间干扰**
- 规模：**118,814 张训练 + 13,342 张验证**（纯 ship + aircraft）
- 类别：**2类** (ship / aircraft)
- 最佳模型 v5-2class-4: P=93.4%, R=93.3%, mAP@50=95.98% ✅ 达到公司要求

#### 验证集说明

所有模型的验证指标均在**独立验证集**上计算，验证集与训练集**无重叠图像**：
- v1: SSDD val split (~232 张，来自 SSDD 官方划分)
- v2/v4/v5: 从 SARDet_100K 随机抽取的 val split (~15-20% 比例)
- 注意：SARDet_100K 本身从 COCO 迁移而来，部分图像来源为光学遥感，非全部实采SAR数据

### 1.5 技术路线

```
SAR图像输入 (GeoTIFF/JPEG, 8bit, P谱段)
  │
  ├─ [M1] 元数据解析 (GDAL)
  │    └─ 提取GSD、地理参考、成像参数
  │
  ├─ [M2] YOLOv8m-OBB 目标检测
  │    └─ 船舶 + 飞机 旋转框检测
  │    └─ 推扫成像切片检测
  │
  ├─ [M3] 坐标地理化
  │    └─ 像素坐标 → WGS84经纬度 (GDAL变换)
  │
  ├─ [M4] 证据融合 (Evidence JSON)
  │    └─ 检测结果 + 坐标 + 元数据 → 结构化证据
  │
  ├─ [M5] LLM通报生成 + Word文档组装
  │    └─ 纯文本LLM读取证据JSON → 情报通报正文
  │    └─ python-docx生成.docx
  │
  └─ 输出：标准通报.docx + 证据JSON + 检测标注图
```

> **设计原则**：事实由检测工具给出，文字由LLM组织——数量/类别/坐标等关键信息来自工具输出，LLM仅负责语言生成，杜绝幻觉。

### 1.6 🔴 SAR域专项说明

#### 我们目前只做SAR

我方所有模型训练、验证、测试**100%基于SAR图像数据**：

| 维度 | 说明 |
|------|------|
| 数据域 | **仅SAR** (合成孔径雷达)，P谱段8bit推扫切片 |
| 未涉及 | 光学遥感 (可见光/红外/多光谱) |
| 模型适配 | YOLOv8m-OBB 在SAR域上fine-tune，未在其他域验证 |
| 域迁移局限 | SAR特有的相干斑噪声、几何畸变、方位模糊等问题，模型已针对性训练 |

**SAR vs 光学关键差异**：
- SAR图像无色彩信息（灰度），目标形态因方位角变化大
- 相干斑噪声 (speckle noise) 是SAR特有，光学图像无此问题
- 目标边缘可能模糊（多普勒效应），需要旋转框适配
- 机场跑道在SAR中呈暗色调（光滑表面镜面反射），港口水域呈暗色调

### 🔴 问题1：机场/港口是场景分类还是目标检测？

**背景**：公司要求中目标类型包括"机场"和"港口"，但未明确检测方式。

**两种方案对比**：

| 维度 | 方案A：场景分类 | 方案B：目标检测 |
|------|----------------|----------------|
| 输出 | 整图判定"此区域为机场/港口" | 定位跑道、停机坪、码头等具体目标 |
| 数据量 | 几千张场景图 | 需标注实例 (跑道轮廓等) |
| 训练难度 | 低 (ResNet/ViT分类) | 高 (需实例级标注) |
| 开发周期 | **1-2周** | **3-4周 + 标注时间** |
| 适用场景 | 粗粒度情报筛选 | 精确目标定位 |

**我方建议**：
- 如果机场/港口用于**区域态势判断** (例如"检测到飞机且在机场附近") → 方案A即可
- 如果需要对机场设施做**精确打击评估** → 需要方案B

**需公司明确**：
- [ ] 机场/港口的最终输出形式是什么？（场景标签 or 目标框 or 两者都要？）

### 🔴 问题3：检测速率 502 MPix/s 是单卡还是允许多卡/集群？

**背景**：这是我方评估后**最大的差距项**。

**当前性能**：
- YOLOv8m 单卡推理: 640×640 ≈ 15-20ms → **约 20-27 MPix/s**
- **与要求差距: 约20倍**

**不同方案预估**：

| 优化方案 | 预期速度 | 精度影响 | 开发周期 |
|----------|----------|----------|----------|
| YOLOv8n (轻量级) | 2-3× | -2~3% mAP | 1周 |
| TensorRT FP16量化 | 2-4× | -0.5~1% mAP | 2周 |
| 批处理优化 (batch=16) | 2-3× | 无 | 1周 |
| INT8量化 | 1.5-2× | -1~3% mAP | 2周 |
| 多卡并行 (2×GPU) | 1.8× | 无 | 2周 |
| 模型剪枝/蒸馏 | 1.5-2× | -1~2% mAP | 2-3周 |

**组合预估**：

| 组合 | 预估速度 | 可行性 |
|------|----------|--------|
| YOLOv8n + TensorRT + batch=16 | **120-240 MPix/s** | ⚠️ 仍差2-4倍 |
| 上条 + 2×GPU并行 | **200-400 MPix/s** | ⚠️ 临界 |
| 上述 + FPGA/专用加速卡 | **400-600 MPix/s** | ✅ 可达标 |

**需公司明确**：
- [ ] 502 MPix/s 是硬件平台的总带宽要求还是算法处理速率？
- [ ] 允许使用几块GPU/加速卡？
- [ ] 平台硬件规格固定还是可以推荐配置？
- [ ] 能否接受轻微精度下降 (2-3% mAP) 换取速度？
